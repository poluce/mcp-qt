## 一、官方 2026-07-28 规范真实内容（changelog 摘要）

1. **移除协议级会话**：删除 `Mcp-Session-Id` header；`initialize`/`notifications/initialized` 握手整体移除（SEP-2575/2567）。
2. **无状态核心**：每个请求必须在 `_meta` 携带 `io.modelcontextprotocol/protocolVersion`（**必需**）与 `io.modelcontextprotocol/clientCapabilities`（**必需**）；`clientInfo` 为 SHOULD。缺失必需字段 → `-32602` + HTTP 400。
3. **`server/discover`**：服务端 **MUST** 实现；客户端 MAY 调用。
4. **`subscriptions/listen`**：取代 HTTP GET stream 与 `resources/subscribe`/`resources/unsubscribe`（SEP-2575）。
5. **移除** `ping`、`logging/setLevel`、`notifications/roots/list_changed`；日志级别改为每请求 `_meta[io.modelcontextprotocol/logLevel]`。
6. **MRTR**（SEP-2322）：`resultType:"input_required"` + `inputRequests` + `requestState`，客户端重试并回传 `inputResponses`；**新的 JSON-RPC id**。
7. **所有结果必须携带 `resultType`**：`"complete"` / `"input_required"` / 扩展值；客户端对未知值 **MUST** 视为无效；对旧版服务器缺省视为 `"complete"`。
8. **Header 路由**（SEP-2243，**REQUIRED**）：
   - `Mcp-Method`：所有请求必带；
   - `Mcp-Name`：`tools/call`→`params.name`、`resources/read`→`params.uri`、`prompts/get`→`params.name`；
   - 非 ASCII/不安全值必须 Base64 sentinel 编码（`=?base64?...?=`）。
9. **`x-mcp-header`**：服务端可在工具 schema 注解参数 → 客户端 **MUST** 支持，镜像为 `Mcp-Param-{Name}` header，并校验约束、拒绝非法工具定义。
10. **CacheableResult**（SEP-2549）：`tools/list`、`prompts/list`、`resources/list`、`resources/read`、`resources/templates/list` 结果要求 `ttlMs` + `cacheScope`。
11. **授权硬化**：RFC 9207 `iss` 校验（客户端 **MUST**）；DCR 必须带 `application_type`（**MUST**）；客户端凭据必须按 issuer 绑定/隔离（**MUST**）。
12. **错误码分区**：`-32000..-32019` 为 legacy（新实现 SHOULD NOT 使用）；`-32020..-32099` 归规范定义。`-32020`=HeaderMismatch、`-32021`=MissingRequiredClientCapability、`-32022`=UnsupportedProtocolVersion。
13. **错误码变更**：资源不存在 `-32002` → `-32602`。

## 二、本地实现对照结论

### ✅ 已实现（stateless 核心三大件）

| 规范项 | 本地实现 | 证据 |
|---|---|---|
| 无握手（initialize 移除） | stateless 模式下 `initialize` 短路报错 | `McpClientSession.cpp:462` |
| `_meta` 必需字段 | 双键注入 protocolVersion / clientCapabilities | `McpClientSession.cpp:1377-1396` |
| `server/discover` | 异步 + 同步 API，解析全字段 | `McpClientSession.cpp:575-630` |
| MRTR | 拦截 input_required、原样回显 requestState、新 id 重发、无 handler 不悬空 | `McpClientSession.cpp:297-350, 1399-1415` |
| Header 路由 Mcp-Method/Mcp-Name | 三类方法映射 | `QtStatelessHttpTransport.cpp:96-126` |

### ❌ 核心问题清单（按严重度排序）

#### 严重级（客户端 MUST 级缺失 / 会导致真实互操作失败）

**P1. `Mcp-Name` / `Mcp-Param-*` 的 Base64 sentinel 编码完全缺失**
- 规范：非安全 ASCII 值（非 ASCII、控制字符、首尾空白、命中 sentinel 模式）必须编码为 `=?base64?...?=`。
- 本地：`request.setRawHeader("Mcp-Name", QByteArray::fromStdString(nameHeader))` 原样透传。
- 后果：工具名 / 资源 URI 含中文或特殊字符时 header 非法，服务器 `-32020 HeaderMismatch` 拒绝。

**P2. `x-mcp-header` 特性完全缺失（客户端 MUST 支持）**
- 规范：conforming clients MUST mirror 注解参数为 `Mcp-Param-{Name}` header，校验约束，拒绝非法工具。
- 本地：grep 全库无 `x-mcp-header`、`Mcp-Param` 实现。
- 后果：对使用该特性的服务器（如 Google Cloud Spanner 示例）互操作失败。

**P3. 授权硬化（RFC 9207 `iss`）缺失（客户端 MUST）**
- 规范：客户端 **MUST** 在换取授权码前校验授权响应的 `iss` 与记录的 issuer 一致（SEP-2468）。
- 本地：`McpOAuthClient.cpp` 无任何 `iss`/issuer 校验。
- 附带缺失：DCR 的 `application_type`（SEP-837）、凭据按 issuer 绑定存储（SEP-2352）均无。

**P4. `MCP-Protocol-Version` header 默认版本错误**
- 本地 transport 默认 `m_protocolVersion = "2025-11-25"`，依赖 body `_meta` 反哺覆盖 header。
- 后果：一旦 body 无 `_meta`（纯通知等）或调用方未 `setProtocolVersion("2026-07-28")`，发往 2026-07-28 服务器即被 `-32022 UnsupportedProtocolVersion` 拒绝；声称"支持 2026-07-28"但默认行为仍是旧版。

**P5. `subscriptions/listen` 完全未实现**
- 2026-07-28 用 `subscriptions/listen` 取代 `resources/subscribe`/`resources/unsubscribe` 与 HTTP GET stream。
- 本地：grep 无 `subscriptions/listen`；仍只提供旧 `subscribeResource`/`unsubscribeResource`。

#### 中度级（语义偏差 / 覆盖不全）

**P6. `resultType` 未作为通用响应语义处理**
- 规范：所有 result MUST 携带 `resultType`；未知值视为无效；缺省视为 complete。
- 本地：仅 `input_required` 被拦截，其余 result 原样透传，不校验 resultType 存在性与合法性。

**P7. CacheableResult（`ttlMs`/`cacheScope`）仅 server/discover 解析**
- 本地 `tools/list`、`prompts/list`、`resources/list`、`resources/read` 响应未暴露缓存字段。

**P8. 已移除项的残留**
- `ping`、`logging/setLevel`、`notifications/roots/list_changed` 在 2026-07-28 已移除，本地仍保留实现与发送路径。
- `MCP-Session-Id` header 仍被写入（规范已删除协议级会话；虽要求 2026-07-28 服务器忽略，但说明 transport 语义仍是 legacy 混合）。

**P9. 错误码使用违反新分区策略**
- 本地用 `-32000`（MRTR 无 handler）、`-32001`（同步超时）作为自定义错误；二者落在 legacy 区（新实现 SHOULD NOT 使用），且 `-32001` 与旧版 HeaderMismatch 冲突、新规范已重编号为 `-32020`。

**P10. initialize 短路错误语义不准确**
- stateless 下 `initialize` 返回 `-32022`（UnsupportedProtocolVersion），实际应表达"方法不存在"（`-32601` / HTTP 404）。

## 三、结论

本地分支 **完成的是 2026-07-28 的 stateless 核心子集**（`server/discover` + MRTR + `Mcp-Method`/`Mcp-Name` 基本路由），**不是完整协议实现**。

真正"完成协议"还需要补齐的硬性缺口：

1. `Mcp-Name`/`Mcp-Param-*` 的 Base64 编码（P1）
2. `x-mcp-header` 支持（P2）
3. RFC 9207 `iss` 校验 + DCR `application_type` + issuer 凭据绑定（P3）
4. 默认协议版本改为 2026-07-28（P4）
5. `subscriptions/listen`（P5）
6. `resultType` 通用语义（P6）
7. CacheableResult 暴露（P7）
8. 移除项清理（P8）
9. 错误码迁移（P9）
10. initialize 语义修正（P10）

且所有自研场景（`stateless-2026-07-28(-http)`）均为本地 mock server 自测，**没有官方 conformance 2026-07-28 套件的验证记录**。

### 过程中修复的问题

1. **同步 API 死锁**：HTTP transport 依赖 Qt 事件循环，conformance handler 全部改用 `runBlocking` + 异步 API（`*Sync` 会阻塞 main thread 导致超时）。
2. **context 环境变量丢失**：conformance 在 Windows `shell:true` 下传递含中文/换行的 `MCP_CONFORMANCE_CONTEXT` 会丢失，`http-custom-headers` 改用与场景一致的硬编码参数。
3. **iss 校验集成**（SEP-2468）：`McpQtClient::_runOAuthQt` 在换取授权码前校验 redirect 的 `iss`——present 时必须与 metadata issuer 简单字符串匹配（不做 URL 规范化）；缺失但 server 广告支持则拒绝；缺失且未广告则放行。metadata issuer 与 well-known URL 不一致时拒绝使用该 metadata（RFC 8414 §3.3）。
4. **DCR application_type**（SEP-837）：注册请求体补 `"application_type":"native"`。
5. **CIMD URL-based client_id**（SEP-991）：server 广告 `client_id_metadata_document_supported=true` 时跳过 DCR，使用 URL-based client_id。
6. **scope 合并**（SEP-2350）：重新授权时合并先前已请求的 scope（`McpOAuthClient::requestedScopes/recordRequestedScopes`）。
7. **拒绝场景快速失败**：OAuth 拒绝（iss 校验失败等）后客户端立即退出，避免 30s 超时。

### 结论

官方 conformance 2026-07-28 客户端场景**全部通过**（32/32 场景，累计 440+ checks，0 failures 0 warnings）。扩展（extension）属性场景（dpop/wif-jwt/enterprise-managed-authorization 等）不在 2026-07-28 过滤范围内，未纳入。

回归：全量编译通过、单元测试 27/27（159/0 断言）、本地端到端 7/7 PASS 均保持绿色。
