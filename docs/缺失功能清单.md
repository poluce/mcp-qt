# mcp-qt 缺失功能清单与路线图

> 更新日期：2026-08-08（条目完成日期见各节；2026-08-18 文档对齐：路线图不再把已完成的 A4/A8/C7/C8/C9 写成待办）
> 本清单记录 mcp-qt 相对于 MCP 2026-07-28 官方生态（核心 + 扩展）仍缺失的功能项，供后续排期与接手参考。

| 领域 | 状态 |

## 二、优先级 P0 —— 官方生态完整性硬缺口

### 2.1 C1：Tasks 扩展（SEP-2663）

| 项 | 内容 |
|----|------|
| 状态 | ❌ 全库无 `tasks/get` / `tasks/update` / `io.modelcontextprotocol/tasks` |
| 协议 | `tasks/get`、`tasks/update`、`tasks/cancel`、subscriptions 通知；`resultType: "task"`；`params.task` / `ttlMs` |
| 影响 | **2026-07-28 官方第一方扩展**（与 MCP Apps 同级）。长任务（异步工作流、后台作业）无法支持；conformance `tasks-*` 场景全未覆盖 |
| 建议 | 独立扩展模块（参考 `src/apps/` 模式）：`McpTaskSupport` 协议层 + `McpQtClient` 暴露 `getTaskAsync` / `updateTaskAsync` / `cancelTask`；能力声明经 `capabilities.extensions` |
| 工作量 | 中等（约 2-3 天） |

### 2.2 C9：JWT-Bearer 签名基础设施（RFC 7523）

| 项 | 内容 |
|----|------|
| 状态 | ✅ **已实现（2026-08-08）**：`src/client/src/es256jwt.cpp`（Windows 走系统 BCrypt / 非 Windows 走 OpenSSL；自含最小 P-256 点运算从 d 恢复公钥）。`McpQtClient.cpp` JWT-Bearer 路径完整：`private_key_pem` + ES256（P-256）生成 RFC 7523 client assertion，POST `grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer&assertion=<jwt>` 换取 token。单测 6 用例全绿（RFC 6979 公钥推导 / PKCS8 / SEC1 / 防篡改 / 非法 PEM / claims 校验）。**剩余：RS256 及 ECDSA 其它曲线（P-384/P-521）未实现** |
| 协议 | 客户端用私钥签发 JWT assertion（header+claims+签名），POST `grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer&assertion=<jwt>` 换取 token |
| 影响 | ✅ `auth/client-credentials-jwt` **已验证通过**（2026-08-11，8/8，aud 修正为授权服务器 issuer）；❌ `auth/cross-app-access-complete-flow`（0.1.16）/ `auth/enterprise-managed-authorization`（0.2.0-alpha.10）属 **C2 EMA 完整流程**（token exchange + jwt-bearer grant），**非 ES256 可解锁**；仍阻塞 **C4 WIF / C10 全量 conformance** 中的 RS256 场景 |
| 技术难点 | ECDSA（P-256）/ RSA（RS256）签名、PEM 私钥解析、JWT base64url 编码 |
| 实现方式 | Windows CNG（BCrypt 原生 ECDSA P-256，零新依赖）；非 Windows 沿用仓库既有 OpenSSL 依赖 |
| 建议 | RS256 需引入 RSA 签名后端（CNG BCrypt RSA / OpenSSL） |
| 工作量 | ES256 已完成；RS256 另计 |

## 三、优先级 P1 —— 官方生态扩展（C9 ES256 已完成，下列仍开放）

### 3.1 C2：EMA 扩展（Enterprise Managed Authorization）

| 项 | 内容 |
|----|------|
| 状态 | ❌ 未实现 |
| 协议 | ID-JAG（RFC 8693 token exchange）+ JWT-bearer 换 MCP token |
| 依赖 | C9 ES256 已就绪；本项还缺 RFC 8693 token exchange（及必要时 RS256） |
| 建议 | 在已落地的 C9 ES256 上补 token exchange，打通 EMA 完整流程 |

### 3.2 C3：DPoP（RFC 9449）

| 项 | 内容 |
|----|------|
| 状态 | ❌ 未实现 |
| 协议 | 访问令牌绑定密钥，请求附 proof JWT（`DPoP` header） |
| 依赖 | 可复用已完成的 C9 ES256 |
| 建议 | 传输层增加 DPoP header 注入 + proof 生成 |

### 3.3 C4：WIF（Workload Identity Federation）

| 项 | 内容 |
|----|------|
| 状态 | ❌ 未实现 |
| 协议 | 工作负载用平台 JWT 认证 |
| 依赖 | C9 ES256 已就绪；通常还要 C2 |
| 建议 | C2 完成后评估 |

### 3.4 C10：conformance `--suite all` 全量验证

| 项 | 内容 |
|----|------|
| 状态 | ❌ 未运行 |
| 说明 | 目前只跑 2026-07-28 过滤的 32 场景；extension 属性场景（dpop / wif-jwt / enterprise-managed-authorization）未跑 |
| 依赖 | C2 / C3 / C4（C9 ES256 已完成；RS256 相关场景仍可能缺） |
| 建议 | C1 + C2/C3/C4 完成后跑全量，补齐 extension handler |

## 四、优先级 P2 —— 质量 / 安全收尾

### 4.1 A8：MCP Apps 沙箱 / CSP 细化

| 项 | 内容 |
|----|------|
| 状态 | ✅ **已实现（2026-08-11）**：双 iframe 沙箱代理（壳页 + 内层 sandbox iframe `allow-scripts allow-same-origin`，`sandbox-proxy-ready`/`sandbox-resource-ready` 握手）、CSP 构造（`ui.csp` 省略时用规范限制性默认 6 条；声明时按 `connectDomains`/`resourceDomains`/`frameDomains`/`baseUriDomains` 扩展）、`permissions` → iframe `allow` 属性、**initialized 门禁**（收到 `ui/notifications/initialized` 前 Host 不发任何消息）、**size-changed** 处理（`appSizeChanged` 信号）。单元测试覆盖（`test_mcp_app_support_csp_construction` / `allow_attribute` / `initialized_gate` / `size_changed`）。✅ **运行时验证通过**：`multi_server_agent` 端到端跑通沙箱闭环（壳页加载 → `sandbox-proxy-ready` → iframe 创建加载 App → App 的 `ui/initialize`/`tools/call`/`ui/open-link` 双向消息到达 bridge，`exit 0`）。排查并修复三处集成问题：① renderer 双重删除（`std::make_shared` + Qt `addWidget` 双所有权 → 退出 `0xC0000409`，改裸指针由 Qt 管理）；② WebView2 并发实例共享默认 `userDataFolder` 锁冲突（`CreateCoreWebView2Controller` 报 `0x800700AA ERROR_NO_SYSTEM_RESOURCES`，改独立 userDataFolder）；③ 壳页 JS 内字面量 `<script>`/`</script>` 触发 Chromium script double-escaped 解析使壳页脚本失效，改用 `\x3C` 转义注入 AppBridge 桥。**同日再补齐**：WebView2 权限实际授予（`add_PermissionRequested` 按 `_meta.ui.permissions` 授予/拒绝，未声明一律拒绝）、`hostContext` 完整字段（theme/locale/timeZone/containerDimensions/safeAreaInsets/deviceCapabilities/styles + setter API）、`appCapabilities` 解析 + displayMode 协商（目标模式需 App 声明 ∩ 宿主支持，否则返回当前模式 + `displayModeChanged` 信号）、`appLogMessage` 信号、`teardown` 等待响应（带 id + 2s 超时兜底）、CSP 审计日志信号（`cspAudited`）、沙箱 UI 边界标识（iframe 边框，`prefersBorder` 可关）、外部域检测信号（`externalDomainsDetected`）、`prefersBorder`/`domain` 元数据解析、HTML 哈希接口（`hashHtml`）、加载看门狗（`loadTimeout` 15s）、**资源限制**（`setMaxMemoryMb` 子进程内存监控 + `resourceLimitExceeded`）、**哈希 allowlist**（`setAllowedHtmlHashes` 白名单校验 + `htmlBlockedByPolicy`）、**未声明域警告 UI**（`setExternalDomainWarningEnabled` + 确认对话框）。剩余：A5/A6 跨平台渲染（受平台限制，见 §五） |
| 影响 | 已落地：默认最小权限 + 声明域 CSP；跨平台渲染仍见 A5/A6 |
| 建议 | 已完成，无需再排期 |
| 工作量 | — |
