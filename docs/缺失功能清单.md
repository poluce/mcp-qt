# mcp-qt 缺失功能清单与路线图

> 更新日期：2026-08-08
> 本清单记录 mcp-qt 相对于 MCP 2026-07-28 官方生态（核心 + 扩展）仍缺失的功能项，供后续排期与接手参考。

---

## 一、总体状态

| 领域 | 状态 |
|------|------|
| MCP 2026-07-28 核心协议（stateless/MRTR/Header 路由/OAuth 硬化） | ✅ 已完成，官方 conformance 32/32 全绿 |
| 旧协议（2025-11-25 等）向后兼容 | ✅ 大部分保留，2 个 JWT 相关场景失败 |
| **MCP Apps 扩展（io.modelcontextprotocol/ui）** | ✅ 核心已补齐（AppBridge 工具代理/权限/方言） |
| **Tasks 扩展（io.modelcontextprotocol/tasks）** | ❌ **未实现** |
| 认证扩展（EMA / DPoP / WIF / JWT-Bearer） | ❌ 未实现（JWT 签名为基座） |
| 服务端角色 | ❌ 未实现（SDK 定位客户端） |

---

## 二、优先级 P0 —— 官方生态完整性硬缺口

### 2.1 C1：Tasks 扩展（SEP-2663）

| 项 | 内容 |
|----|------|
| 状态 | ❌ 全库无 `tasks/get` / `tasks/update` / `io.modelcontextprotocol/tasks` |
| 协议 | `tasks/get`、`tasks/update`、`tasks/cancel`、subscriptions 通知；`resultType: "task"`；`params.task` / `ttlMs` |
| 影响 | **2026-07-28 官方第一方扩展**（与 MCP Apps 同级）。长任务（异步工作流、后台作业）无法支持；conformance `tasks-*` 场景全未覆盖 |
| 建议 | 独立扩展模块（参考 `src/apps/` 模式）：`McpTaskSupport` 协议层 + `McpQtClient` 暴露 `getTaskAsync` / `updateTaskAsync` / `cancelTask`；能力声明经 `capabilities.extensions` |
| 工作量 | 中等（约 2-3 天） |

### 2.2 C9：JWT-Bearer 签名基础设施（RFC 7523）

| 项 | 内容 |
|----|------|
| 状态 | ⚠️ 仅骨架。`McpQtClient.cpp` 已识别场景并解析 `signing_algorithm`，但 **`// TODO: 生成 JWT assertion` 断点**，ES256/RS256 实际签名未实现 |
| 协议 | 客户端用私钥签发 JWT assertion（header+claims+签名），POST `grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer&assertion=<jwt>` 换取 token |
| 影响 | ① 旧协议 conformance 2 个真实失败（`auth/client-credentials-jwt`、`auth/cross-app-access-complete-flow`）；② **阻塞 C2 EMA / C4 WIF / C10 全量 conformance** |
| 技术难点 | ECDSA（P-256）/ RSA（RS256）签名、PEM 私钥解析、JWT base64url 编码。当前仅链接 Windows `bcrypt`（SHA-256），无签名能力 |
| 可选方案 | ① Windows CNG（原生 RSA/ECDSA，零新依赖）；② OpenSSL（引入依赖，与零外部库定位冲突）；③ 纯算法实现（不现实） |
| 建议 | 优先 Windows CNG；跨平台预留接口（Linux 可走 OpenSSL 或系统库） |
| 工作量 | 中（约 1-2 天，不含跨平台） |

## 三、优先级 P1 —— 官方生态扩展（依赖 C9）

### 3.1 C2：EMA 扩展（Enterprise Managed Authorization）

| 项 | 内容 |
|----|------|
| 状态 | ❌ 未实现 |
| 协议 | ID-JAG（RFC 8693 token exchange）+ JWT-bearer 换 MCP token |
| 依赖 | **C9 JWT 签名** |
| 建议 | C9 落地后实现 token exchange 流程 |

### 3.2 C3：DPoP（RFC 9449）

| 项 | 内容 |
|----|------|
| 状态 | ❌ 未实现 |
| 协议 | 访问令牌绑定密钥，请求附 proof JWT（`DPoP` header） |
| 依赖 | JWT 签名（可复用 C9） |
| 建议 | 传输层增加 DPoP header 注入 + proof 生成 |

### 3.3 C4：WIF（Workload Identity Federation）

| 项 | 内容 |
|----|------|
| 状态 | ❌ 未实现 |
| 协议 | 工作负载用平台 JWT 认证 |
| 依赖 | C9 JWT 基础设施 |
| 建议 | 依赖 C9/C2 完成后评估 |

### 3.4 C10：conformance `--suite all` 全量验证

| 项 | 内容 |
|----|------|
| 状态 | ❌ 未运行 |
| 说明 | 目前只跑 2026-07-28 过滤的 32 场景；extension 属性场景（dpop / wif-jwt / enterprise-managed-authorization）未跑 |
| 依赖 | C9（或至少 C3/C4 的 JWT 支撑） |
| 建议 | C1 + C9 完成后跑全量，补齐 extension handler |

---

## 四、优先级 P2 —— 质量 / 安全收尾

### 4.1 A8：MCP Apps 沙箱 / CSP 细化

| 项 | 内容 |
|----|------|
| 状态 | ⚠️ WebView2 默认隔离；规范要求 Host **必须**执行的 CSP（`default-src 'none'; script-src 'self' 'unsafe-inline'; connect-src 'none'` 等）与权限策略未落实 |
| 影响 | MCP Apps 安全模型不完整；对声明外部域名的 App 无 CSP 控制 |
| 建议 | 解析 `resources/read` 响应的 `_meta.ui.csp` / `permissions`，构造 CSP + iframe `allow` 属性；默认最小权限 |
| 工作量 | 1 天 |

### 4.2 A4：MCP Apps 真实服务器端到端

| 项 | 内容 |
|----|------|
| 状态 | ⚠️ 仅本地 HTML / mock 验证；未连真实 MCP Apps 服务器 |
| 影响 | "支持 MCP Apps"无真实互操作实证 |
| 建议 | 用 ext-apps 官方示例服务器（`threejs-server` / `map-server` 等）联调；验证 ui:// 资源获取 + AppBridge 工具代理闭环 |
| 工作量 | 0.5-1 天 |

### 4.3 C6：MRTR sampling / roots 路径专项验证

| 项 | 内容 |
|----|------|
| 状态 | ⚠️ 现有 MRTR 测试只覆盖 `elicitation/create`；`sampling/createMessage`、`roots/list` 走 inputRequests 的路径无测试 |
| 影响 | 双向能力 MRTR 化覆盖不全 |
| 建议 | 补充 mock 测试：inputRequests 含 sampling / roots 方法时正确回传 InputResponses |
| 工作量 | 0.5 天 |

## 五、按需 / 非核心

| 编号 | 项目 | 说明 |
|------|------|------|
| A5 | QCefView 渲染后端 | `IMcpAppRenderer` 抽象已预留；跨平台需要时实现（需 MSVC + Qt MSVC 包） |
| A6 | 跨平台渲染 | WebView2 仅 Windows；macOS（WKWebView）/ Linux（WebKitGTK）后端 |
| C5 | 服务端角色 | 本项目定位是**客户端** SDK；服务端为全新领域，评估必要性 |

## 六、建议执行顺序

| 阶段 | 内容 | 解锁 |
|------|------|------|
| **Phase A**（当前） | **C1 Tasks 扩展** | 官方生态第二块拼图 |
| **Phase B** | **C9 JWT 签名** → C2/C3/C4 → C10 全量 | 旧协议全绿 + EMA/DPoP/WIF + conformance 全量 |
| **Phase C** | A8 CSP → A4 真实联调 → C6 测试 | MCP Apps 安全与实证完整 |
| **Phase D** | A5/A6 跨平台、C5 服务端（按战略） | 平台覆盖 |
